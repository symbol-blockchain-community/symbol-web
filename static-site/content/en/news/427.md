# September 2026 Blog (Translated from the Japanese Translation)

Good morning, everyone! How are you doing?

I spent September making the game almost without taking a break, so right now I am absolutely bursting with energy... feeling “F-A-N-T-A-S-T-I-C.”

Before I show you how much my beloved little game has grown, let me briefly tell you about work first 😄

## Summary of the Work Done

- **Content Writing**
`NEM`: In August, the Symbol developer tutorials were revamped to use statically typed descriptors, and Java versions of the code were added. In September, it was the NEM documentation’s turn.

  Fortunately, both ChatGPT and I have plenty of experience with this work, so although it was quite a large undertaking, we managed to finish it relatively quickly. [Take a look at the results](https://docs.nemtest.net/en/devbook/start/setup/)!

- **Reviews**
`Symbol`: I carried out the final review of the Java documentation created in August and its Japanese translation.

- **Site Structure**
 I fixed CI build errors caused by dependency updates and brought all the recent improvements to the Symbol documentation site over to the NEM documentation site. I also added redirects from old NEM pages to their new equivalents.

 - **Management**
This section used to mean “documentation management,” but lately it has been more about “game management” 😁

 Currently, *all* of our in-house artists are involved in “XYM City 3D” to varying degrees, so coordination is needed across the team. For the vertical-slice demo, I created a preliminary list of assets and prioritized them in the order they will be needed. Location and character concept art, three-view character drawings, 3D character models and animations, the city map, textures, sound effects, music, dialogue... everything is now organized in a database!

 This was originally supposed to be our first simple game, so perhaps we are getting a little carried away... but I do not regret it one bit! 😅

## Symbol Bridge

**Several people have asked about the bridge, so here is a brief update.**

In September, the team mainly worked on finishing internal monitoring tools for insufficient balances, problems with external services, and the overall health of the bridge. As explained on the official Symbol Bridge documentation page, this bridge is a centralized service operated by The Symbol Syndicate, rather than a decentralized, trustless exchange system between users. That is why we need a solid, robust monitoring setup before making it publicly available.

The bridge will be released to the public once the new wallet, which will serve as its main frontend, is complete. The Symbol wallet code is almost finished and is now in the cleanup and testing stage. Since it will also serve as the basis for the NEM wallet, development of the NEM wallet is expected to speed up considerably.

## XYM City 3D

**On to game development!** XYM City in the morning, XYM City at night, sleep, wake up, and repeat. No weekends off, either.

My wife is already thoroughly fed up with those days, but we have only just begun. Oh, honey, please bear with me a little longer; I promise to make it worthwhile! 💪🏻

As the project lead, I wear several hats. Let me show you a few of them!

- **Writer**: This is a story-driven game, so the story leads the other elements. I know what themes I want to talk about, so I write their outline into the game design document (GDD). Then I divide that into game missions. Missions are like chapters in a novel, and players can experience them in more or less any order.

    Then I write the dialogue for the missions. Besides text, dialogue files can contain arbitrary commands such as “open a door” or “add a new mission objective.” This approach is very flexible, and things are going smoothly so far.

<img width="783" height="240" alt="Image" src="../images/September2026_DocsBlogs_2.png" />

- **Developer**: Godot handles 3D rendering and physics, but we need to write the game-specific code that controls them ourselves.:
    - User interface: the map screen (and navigation), the journal screen (to keep track of active missions), and the message screen
    - Game mechanics: locked doors, exploration, NPC movement routes, and so on

I am implementing all of this in GDScript, with a little help from Codex.

- **Director**: This project began as my personal idea. I want the other team members to contribute their own creativity too, but they still seem a little reserved, so for now I am giving everyone directions.

    I do not want to keep directing everything forever, so I make sure the GDD (game design document) stays up to date and provide plenty of asset-management tables where artists can see what to work on next. This is extremely important when team members are spread around the world. Otherwise, I would end up working 24 hours a day.

<img width="1166" height="1021" alt="Image" src="../images/September2026_DocsBlogs_3.png" />

In the end, I am having an absolutely wonderful time. Compared with the days when I first started making games in a warehouse with two friends, I sometimes miss being able to gather everyone together and discuss every detail. On the other hand, we now have the resources to create something substantial. 😎

## What Is Next

The current top priority for the game is completing the vertical slice. This is a playable demo set in a small area that covers most of the game mechanics, allowing us to evaluate whether the game is actually fun to play.

To do that, we need to:

- Finish implementing the necessary game mechanics.
- Develop the main missions in a little more depth, including objectives, dialogue, and progression.
- Keep adding assets such as maps, characters, and animations.

At the same time, we need to keep developing the production pipeline and start looking for the remaining team members. Well, I love making maps, but I do not expect a famous game studio like **id Software** to recruit me anytime soon! 😅
