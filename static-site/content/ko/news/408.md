## 2026년 3월 Anthony’s Engineering Blog (일본어 번역)

먼저 Hack+ 2026 이벤트의 수상자 여러분께 축하의 말씀을 전합니다 🎉. 해커톤에서 입상하지 못했더라도 낙담하지 마세요. 이 경험을 통해 분명 소중한 배움을 얻었을 것입니다. 포기하지 말고 계속 최선을 다해 주세요!

3월은 여러 가지 일이 마침내 하나로 모이기 시작했다고 느낀 한 달이었습니다. 개발 작업의 대부분은 계속해서 NEM Explorer 백엔드에 집중했습니다. 드디어 네임스페이스 모듈을 완성하고 모자이크와 트랜잭션 데이터베이스 스키마 작업을 시작했습니다. 아직 해야 할 일이 많지만 백엔드는 조금씩 모습을 갖추고 있습니다.

GPT-5.4가 출시된 것도 매우 자극적인 일이었습니다. AI는 점점 더 똑똑해지고 기능도 풍부해지고 있습니다. 저는 개선된 점과 개발 워크플로에 활용하는 방법을 알아보기 위해 대부분의 시간을 조사와 연구에 쏟고 있습니다.

## 주요 업무 요약

- 네임스페이스 모듈 개발을 완료하고 병합했습니다
- 모자이크 모듈 개발을 시작했습니다
- 트랜잭션 데이터베이스 스키마를 재설계했습니다
- REST API 테스트를 리팩터링하고 코드 중복을 줄였습니다

## 각 업무에 대하여

**네임스페이스 모듈**

- 블록에서 네임스페이스 등록 정보를 추출하고 **루트 네임스페이스**, **하위 네임스페이스**, **소유권**, **만료** 정보를 데이터베이스에 저장하는 워크플로를 완료했습니다.
- 프런트엔드가 개별 루트 네임스페이스와 하위 네임스페이스를 조회하고 페이지가 나뉜 네임스페이스 목록을 가져올 수 있도록 `/namespace/<name>` 및 `/namespaces` 엔드포인트를 추가했습니다.
- 피드백에 대응한 뒤 병합했습니다.

**모자이크 모듈**

- 블록 처리에서 **모자이크 정의** 및 **모자이크 공급량 변경** 트랜잭션 처리를 완료했습니다.
- `/mosaic/<namespace>`, `/mosaics`, `/mosaic/rich/list` 엔드포인트를 추가했습니다.
- PR을 만들었으며 현재 팀의 검토를 기다리고 있습니다.

**트랜잭션 스키마 재설계**

- 처음 설계에서는 서로 다른 트랜잭션 유형을 각각 별도의 정규화된 테이블에 저장했습니다. 보기에는 깔끔했지만 전체 트랜잭션을 가져오려면 조인이 너무 많아져 성능에 악영향을 줄 수 있었습니다.
- 그래서 지원되는 모든 트랜잭션 유형을 저장할 수 있는 하나의 트랜잭션 테이블로 전환하기로 했습니다. 스키마 설계는 완료했으며 각 유형에 대응하는 처리 로직 구현을 시작했습니다.

**유닛 테스트 리팩터링**

- 유닛 테스트는 통과했고 코드의 테스트 커버리지도 충분했지만, 코드의 유지보수성을 높이는 것도 중요했습니다. 그래서 반복적으로 수행되던 페이지네이션, 정렬, 데이터 누락 확인을 재사용 가능한 헬퍼 함수로 추출하여 REST API 테스트를 리팩터링했습니다.
- 
## 다음 예정

네임스페이스 모듈 개발은 완료되어 병합되었고, 모자이크 모듈은 현재 팀의 검토를 기다리고 있습니다. 그동안 새로운 단일 테이블 설계를 사용하여 각 트랜잭션 유형의 트랜잭션 처리를 계속 구현할 예정입니다. 상당한 작업량이지만 Explorer의 트랜잭션 쿼리를 위한 기반을 더 단순하고 효율적으로 만들 수 있을 것입니다.
