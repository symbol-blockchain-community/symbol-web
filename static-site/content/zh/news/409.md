## 2026年3月 Anthony’s Engineering Blog（日文译）

首先，祝贺 Hack+ 2026 活动的所有获奖者 🎉。即使没有在黑客松中获奖，也不要气馁。你一定从这次经历中学到了宝贵的东西。不要放弃，请继续努力！

3月让我感觉到，几件事情终于开始逐渐汇聚到一起。大部分开发工作仍然集中在 NEM Explorer 的后端上。我终于完成了命名空间模块，并开始着手处理马赛克和交易数据库的架构。还有很多工作要做，但后端正在逐步成形。

GPT-5.4 的发布也让这个月充满了刺激。AI 正变得越来越聪明，功能也越来越丰富。我一直在专心研究和探索它的改进之处，以及如何将其用于开发工作流。

## 主要工作概览

- 完成并合并命名空间模块的开发
- 开始开发马赛克模块
- 重新设计交易数据库架构
- 重构 REST API 测试，减少代码重复

## 各项工作详情

**命名空间模块**

- 完成了从区块中提取命名空间注册信息，并将**根命名空间**、**子命名空间**、**所有权**及**有效期**信息保存到数据库的工作流程。
- 添加了 `/namespace/<name>` 和 `/namespaces` 端点，使前端可以查询单独的根命名空间或子命名空间，并获取分页的命名空间列表。
- 根据反馈进行了处理，并完成了合并。

**马赛克模块**

- 完成了区块处理中**马赛克定义**和**马赛克供应量变更**交易的处理。
- 添加了 `/mosaic/<namespace>`、`/mosaics` 和 `/mosaic/rich/list` 端点。
- 创建了 PR，目前正在等待团队审核。

**交易架构重新设计**

- 最初的设计是将不同的交易类型分别存储在不同的规范化表中。这种方式看起来很整洁，但要获取完整的交易数据就需要过多的连接，可能会对性能产生负面影响。
- 因此，我决定改用一个可以存储所有受支持交易类型的单一交易表。架构设计已经完成，并开始实现各类型对应的处理逻辑。

**单元测试重构**

- 单元测试已经通过，代码测试覆盖率也很充分，但提高代码的可维护性同样重要。因此，我将反复出现的分页、排序和数据缺失检查提取为可复用的辅助函数，对 REST API 测试进行了重构。
- 
## 接下来的计划

命名空间模块的开发已经完成并合并，马赛克模块目前正在等待团队审核。在此期间，我将使用新的单表设计继续实现各交易类型的交易处理。这项工作量相当大，但应该能为 Explorer 的交易查询提供更简单、更高效的基础。
