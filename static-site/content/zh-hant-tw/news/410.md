## 2026 年 3 月 Anthony’s Engineering Blog（日文翻譯）

首先，恭喜 Hack+ 2026 活動的所有得獎者 🎉。即使沒有在駭客松中獲獎，也不要氣餒。你一定從這次經驗中學到了寶貴的東西。不要放棄，請繼續努力！

3月讓我感覺到，幾件事情終於開始逐漸匯聚到一起。大部分的開發工作仍然集中在 NEM Explorer 的後端。我終於完成了命名空間模組，並開始著手處理馬賽克和交易資料庫的綱要。還有很多工作要做，但後端正逐步成形。

GPT-5.4 的發佈也讓這個月充滿了刺激。AI 正變得越來越聰明，功能也越來越豐富。我一直專心研究和探索它的改進之處，以及如何將其運用在開發工作流程中。

## 主要工作概覽

- 完成並合併命名空間模組的開發
- 開始開發馬賽克模組
- 重新設計交易資料庫綱要
- 重構 REST API 測試，減少程式碼重複

## 各項工作詳情

**命名空間模組**

- 完成了從區塊中提取命名空間註冊資訊，並將**根命名空間**、**子命名空間**、**所有權**及**有效期限**資訊儲存到資料庫的工作流程。
- 新增了 `/namespace/<name>` 和 `/namespaces` 端點，讓前端可以查詢個別的根命名空間或子命名空間，並取得分頁的命名空間清單。
- 根據回饋進行處理後完成合併。

**馬賽克模組**

- 完成了區塊處理中**馬賽克定義**和**馬賽克供給量變更**交易的處理。
- 新增了 `/mosaic/<namespace>`、`/mosaics` 和 `/mosaic/rich/list` 端點。
- 建立了 PR，目前正在等待團隊審核。

**交易綱要重新設計**

- 最初的設計是將不同的交易類型分別儲存在不同的正規化資料表中。這種方式看起來很整潔，但要取得完整的交易資料就需要過多的連接，可能會對效能產生負面影響。
- 因此，我決定改用一個可以儲存所有受支援交易類型的單一交易資料表。綱要設計已經完成，並開始實作各類型對應的處理邏輯。

**單元測試重構**

- 單元測試已經通過，程式碼測試涵蓋率也很充分，但提高程式碼的可維護性同樣重要。因此，我將反覆出現的分頁、排序和資料缺失檢查提取為可重複使用的輔助函式，對 REST API 測試進行了重構。
- 
## 接下來的計畫

命名空間模組的開發已經完成並合併，馬賽克模組目前正在等待團隊審核。在此期間，我將使用新的單一資料表設計繼續實作各交易類型的交易處理。這項工作量相當大，但應該能為 Explorer 的交易查詢提供更簡單、更有效率的基礎。
